# รูปแบบมอบงานระหว่างตำแหน่ง (Handoff)

หน้าที่ของเอกสารนี้: กำหนดรูปแบบที่ตำแหน่งใหม่ (A01–A06) ใช้ส่งงานต่อให้ตำแหน่งเดิม และรายงานผลกลับ
กฎของโปรเจกต์อยู่ที่ [AGENTS.md](../AGENTS.md) แผนรวมอยู่ที่ [agent-org-v2-plan.md](agent-org-v2-plan.md)

ทุกการส่งงานข้ามตำแหน่งต้องมี `jobId` เดียวกันตลอด เพื่อให้ตามรอยได้ว่าใครส่งอะไรให้ใคร และรายงานไม่มีงานค้าง

## รูปแบบ

```json
{
  "jobId": "J-2026-10-21-01",
  "from": "A04",
  "to": "menu",
  "goal": "คิดราคา 80 กล่อง งบ 120 บาทต่อกล่อง วันที่ 12 พ.ย. ส่งสำนักงาน",
  "context": { "people": 80, "date": "2026-11-12", "location": "สำนักงานใกล้อโศก", "budgetPerBox": 120 },
  "acceptance": [
    "ราคาต่อกล่องมาจากฐานเมนูกลาง",
    "ค่าส่งตามนโยบาย adminQuote ไม่แต่งตัวเลข"
  ],
  "files": ["data/business-rules.json:delivery.policy"],
  "checks": ["node scripts/check-business-sync.mjs --check"]
}
```

| ฟิลด์ | ต้องมี | กฎ |
|---|---|---|
| `jobId` | เสมอ | รูปแบบ `J-<วันที่>-<ลำดับ>` เช่น `J-2026-10-21-01` |
| `from` / `to` | เสมอ | รหัสตำแหน่ง เช่น `A04`, `menu`, `structure` |
| `goal` | เสมอ | บรรทัดเดียว ระบุว่าต้องได้อะไร ไม่ใช่วิธีทำ |
| `context` | เมื่อมีข้อมูลลูกค้า | จำนวนคน วันที่ สถานที่ งบ เงื่อนไขพิเศษ |
| `acceptance` | เสมอ | เกณฑ์ที่ผู้รับต้องผ่าน เขียนเป็นข้อเท็จจริงที่ตรวจได้ |
| `files` | เมื่อแตะไฟล์ | รูปแบบ `ไฟล์:บรรทัด` ถ้ายังไม่รู้ตำแหน่ง ให้ขอ `scout` หาเป้าก่อน |
| `checks` | เมื่องานแตะโค้ดหรือข้อมูลธุรกิจ | คำสั่งที่ผู้รับต้องรัน |

## กฎการส่งและรับ

1. **ผู้ส่ง** ระบุ `goal`, `context`, `acceptance`, `files` ให้ครบ ถ้ายังไม่รู้ตำแหน่งไฟล์ ให้ขอ `scout` ก่อน — ห้ามส่งงานแบบ “ไปแก้หน้าที่เกี่ยวกับราคา”
2. **ผู้รับ** ตอบกลับเป็นผลลัพธ์มาตรฐานเสมอ (ดู [agent-org-v2-plan.md](agent-org-v2-plan.md) หัวข้อ 6.1) ไม่ใช่ข้อความอิสระ
3. **ผู้รับติดขัด** ตอบ `status: blocked` พร้อมเหตุผลและสิ่งที่ขาด แล้วส่งกลับผู้เรียก — ห้ามเดาและห้ามแก้เพื่อให้ผ่าน
4. **คนละเจ้าของไฟล์ในรอบเดียวกัน** ห้ามมีสองตำแหน่งแก้ไฟล์เดียวกันพร้อมกัน
5. **ตัวเลขธุรกิจ** ผู้รับต้องดึงจากไฟล์จริงด้วย `node tools/agent/context.mjs` หรือ `node tools/agent/menu-match.mjs` ห้ามพิมพ์ตัวเลขจากความจำ
6. **งานที่แตะลูกค้า** ต้องมี audit ใน `services/audit.mjs` และต้องผ่าน `guardian` ก่อนสรุปให้เจ้าของ

## รูปแบบผลลัพธ์มาตรฐาน (ทุกตำแหน่งใช้ร่วมกัน)

```json
{
  "position": "A04",
  "task": "ร่างใบเสนอราคา",
  "status": "done | blocked | needs_approval",
  "data": { },
  "sources": ["file:line | api:route | url"],
  "checks": [{ "command": "node scripts/check-business-sync.mjs --check", "result": "pass" }],
  "next": "สิ่งที่ต้องทำต่อ",
  "escalate": false
}
```

| ฟิลด์ | ความหมาย |
|---|---|
| `status` | `done` ทำเสร็จและตรวจผ่าน · `blocked` ทำต่อไม่ได้เพราะข้อมูลไม่พอ · `needs_approval` รอเจ้าของตัดสินใจ |
| `sources` | ที่มาของทุกตัวเลขและข้อเท็จจริง บังคับไม่ให้ตอบจากความจำ |
| `checks` | คำสั่งที่รันและผล ถ้าไม่ได้รัน ให้เขียนว่า `not run` พร้อมเหตุผล |
| `escalate` | จริงเมื่องานนี้ต้องให้คนตัดสินใจ — ผู้จัดการต้องรายงานต่อเจ้าของ |

## ขอบเขตที่ช่องทางเขียนครอบไว้

ตำแหน่ง A02 และ A04 เขียนผ่าน Internal API ได้เฉพาะ (อนุมัติแล้ว 2026-10-21) ด้วย `node tools/agent/draft.mjs`
เขียนได้: ร่างตอบ · ตั้ง lead ตามกฎของระบบ · ความจำลูกค้า
เขียนไม่ได้: ส่งข้อความ · อนุมัติ · เลื่อนสถานะ lead · แก้ราคา/เมนู · แตะไฟล์เว็บ
